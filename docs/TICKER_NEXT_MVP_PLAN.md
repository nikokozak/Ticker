# Ticker Next MVP Plan

Ticker Next is a hard reset of Ticker’s UX: from a stateful “stream/cell system” to a fast, predictable, text-first writing surface with optional power layers (AI transforms, PDF reading/highlight linking).

This plan intentionally breaks compatibility with existing Ticker streams. We are rescuing backend/service code where it helps, not preserving the prior document model.

## Goals (What We’re Building)

- A native editor that feels like TextEdit: instant input, unsurprising copy/paste, unsurprising undo/redo.
- Notes are portable plain-text Markdown files (`.md`) in a user-chosen library folder.
- AI features operate on selections and behave like normal edits: select -> action -> replace -> single undo.
- PDF reading mode where the PDF is the source of truth, and notes link to PDF highlights (without writing annotations into the PDF file).
- Quick Window is a first-class primary surface (capture-first workflow), not a side feature.

## Non-Goals (MVP)

- No “cells” as a required structure, no per-block state machines, no live-mutating content regions.
- No OCR. If a PDF has no selectable text, highlight/quote features are limited accordingly (Preview-like behavior).
- No RAG in MVP (indexing is allowed for local search, but retrieval-augmented answering is deferred).
- No editing of the PDF itself. No writing PDF annotations. We only store highlight locations and links.

## Product Principles (Contracts)

1. **Content is the contract.**
   - The Markdown file is the source of truth for user-written text.
   - Everything else is an overlay/sidecar that must never make editing surprising.

2. **AI is an edit, not a mode.**
   - AI actions apply to a selection and replace text (or insert at cursor).
   - One undo returns to the pre-AI state.
   - “AI authorship” marking is informative only; it must never affect editing semantics.

3. **No structure before content.**
   - Users can start writing instantly in an empty document.
   - Organizational affordances (folders, wikilinks, search) are optional and additive.

4. **Privacy posture: no blanket screen recording permission.**
   - Prefer clipboard-based image capture and user-initiated file imports.

## Architecture Overview

### UI Stack (Native-First)

- **Editor:** AppKit text system (`NSTextView` / TextKit) embedded in SwiftUI where convenient.
- **PDF reader:** PDFKit (`PDFView`) for rendering + selection.
- Keep WKWebView/React as legacy code until removed; new MVP surfaces are native.

### Library Model (Filesystem)

User selects a **library root folder**. We scan recursively for notes.

Conventions inside the library:

```
<Library>/
  Inbox.md
  <any>.md
  <Project>/<any>.md
  Assets/
    PDFs/<pdfId>.pdf
    Images/<imageId>.<ext>
  .ticker/
    meta/
      docs/<docId>.json
      pdfs/<pdfId>.json
    cache/
      search.sqlite   (optional/derivable)
```

Notes can live at the root or in subfolders (“projects”). The `Assets/` and `.ticker/` folders are created/managed by Ticker Next.

### Markdown Identity (YAML Front Matter)

Each note starts with minimal YAML front matter:

```yaml
---
ticker_id: <uuid>
ticker_kind: note | inbox | pdf_note
ticker_pdf_id: <uuid>            # only for pdf_note
created_at: 2026-02-10T19:30:00Z # optional
---
```

Rationale:
- Transparent and resilient across rename/move/backup.
- Enables stable linking/backlinks without relying on file paths.

Duplicate ID handling:
- On open/scan, detect duplicate `ticker_id` values.
- MVP behavior: surface a clear warning + offer an explicit “Fix duplicate IDs” action that rewrites front matter for the conflicting files.

### Sidecar Metadata (Durable Overlays)

We store overlays in `.ticker/meta/` to keep Markdown portable and readable.

Two durable metadata categories:

1. **AI authorship spans** (per document)
   - Stored as spans keyed by `(docId, startOffset, length)` plus provenance.
   - Rendered as subtle text styling (e.g. slightly different weight/opacity) with a user toggle.
   - Span update rules on edit:
     - Editing inside a span splits/shrinks spans as needed.
     - Newly typed text defaults to “human” unless explicitly generated by an AI action.

2. **PDF highlights** (per PDF)
   - Stored as highlight anchors keyed by `(pdfId, highlightId)`.
   - Anchors include:
     - `pageIndex`
     - selection geometry in page coordinates (rects/quadpoints)
     - selected text (when available)
     - file fingerprint (size/mtime/hash) for drift detection

### PDF Import (Copy Into Library)

- When a PDF is imported, it is copied into `Assets/PDFs/<pdfId>.pdf`.
- A companion note is created (or linked) as `<Title>.md` with `ticker_kind: pdf_note` and `ticker_pdf_id`.
- Ticker Next never writes annotations into the PDF file.

### Linking Notes <-> PDF Highlights

- Notes reference highlights via an explicit link token (format TBD), e.g.:
  - `ticker-pdf://<pdfId>#hl=<highlightId>`
- Clicking a note link jumps the PDF view to the highlight and visually pulses it.
- Creating a highlight offers “Create linked note line at cursor” and “Send to Inbox”.

### AI Integration (Reuse Existing Backend)

Reuse as much of the existing Swift “backend” as possible:
- device key storage (`~/Library/Application Support/...`), never in Markdown
- proxy-only LLM request path, streaming, error mapping, request IDs

New UX contracts:
- AI actions are selection-based operations that produce plain text replacements.
- Persist AI span metadata for the replaced region.

## MVP Milestones (Phased, Testable)

### M0: Scaffold + Guardrails

- New “Ticker Next” mode flag (or parallel window) that does not depend on streams/cells.
- Library root selection (Open Panel) stored via security-scoped bookmark.
- Basic file model + front matter parser/writer + duplicate ID detection.
- Unit tests for:
  - front matter parse/write roundtrip
  - duplicate ID detection and fix action

### M1: Native Markdown Editor (Fast + Boring)

- Create/open/save `.md` notes in the library.
- Instant typing performance; normal copy/paste; undo/redo is predictable.
- Image paste/drag-drop: copy into `Assets/Images/` and insert Markdown image link.
- Unit tests for:
  - asset import path generation
  - Markdown insertion behavior (pure functions, where possible)

### M2: Inbox-First Quick Window

- Quick Window defaults to appending to `Inbox.md`.
- “Send to current note” as an explicit action.
- No screen recording permission required (clipboard image support only).
- Manual smoke checklist for:
  - cold open latency
  - repeated opens (10x) without UI lag

### M3: Selection-Based AI Actions + Authorship Marking

- Right-click (or command palette) actions:
  - Rewrite (custom prompt)
  - Proofread
  - Summarize
- Each action:
  - replaces the selection
  - groups undo so one undo restores the pre-AI text
  - persists AI spans for the inserted text
- Unit tests for:
  - span application rules on edit (split/shrink behavior)
  - span persistence roundtrip

### M4: PDF Reading + Highlight Linking

- Import PDF (copy into library) + create companion `pdf_note`.
- Open PDF view + selectable text highlight flow.
- Create a note link to a highlight (jump back to PDF from note).
- Drift detection: warn if PDF fingerprint changes.
- Unit tests for:
  - pdf fingerprinting
  - highlight serialization roundtrip

### M5: Navigation (Search + Jump)

- Command palette:
  - open note
  - open recent
  - jump to heading (within note)
  - jump to PDF highlight (within a PDF)
- Search implementation options (pick one for MVP):
  - simple in-memory scan for small libraries
  - optional SQLite FTS cache in `.ticker/cache/search.sqlite` (derivable)

## MVP Release Checklist (Definition of “Ready”)

- No data loss in manual restart tests (edit note, quit app, relaunch, verify).
- AI action undo is reliable and never leaves the document in an inconsistent state.
- PDF highlight links are stable across restart.
- No screen recording permission requested.
- Basic performance bar:
  - editor feels instant on first keypress
  - Quick Window open is consistently fast

## Open Questions (Explicitly Deferred)

- Exact highlight link syntax (`ticker-pdf://...` vs markdown reference format).
- Wikilinks/backlinks (`[[Note]]`) and how aggressively to support them in MVP.
- Cross-device sync strategy for `.ticker/meta` and `.ticker/cache`.
- Whether to hide YAML front matter in the editor view (rendered/readonly) vs show as plain text.
